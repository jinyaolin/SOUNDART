# 類比、數位與 Buffer

這一章處理一個在後面幾章會不斷出現、卻很少被說清楚的問題：聲音是空氣的振動，電腦裡存的是數字，兩者是怎麼接起來的。

Pure Data 的 `[osc~]` 為什麼要寫成每秒 44100 個數字？音效設定裡的 block size 到底在調什麼？為什麼把它調小會爆音？這些問題的答案都在這一章。

## 4.5.1 聲音、波形與類比訊號

聲音是介質裡的壓力變化。空氣被推擠的地方壓力升高，被拉開的地方壓力降低，這個疏密的變化以波的形式向外傳。

我們畫的波形圖，描述的是**某一個位置**的壓力如何隨時間改變。橫軸是時間，縱軸是壓力偏離平衡值的量。它不是聲音在空間中的形狀。

波形上有兩個最基本的量。**振幅（amplitude）**是波形離中線多遠，關聯到聲音聽起來的強弱。**頻率（frequency）**是一秒鐘來回幾次，關聯到聽起來的音高。這裡用「關聯」而不是「等於」，因為響度與音高還牽涉聽覺系統的非線性反應，那是另一個題目。

麥克風做的事，是把空氣的壓力變化轉換成電壓變化。波形的形狀沒有改變，只是換了一種物理量來承載它。這種用連續變化的物理量來表示聲音的方式，稱為**類比（analog）**。

類比訊號有一個關鍵性質：在任何一個時間點上它都有值，沒有「中間空白」。這一點正好是數位化要打破的。

## 4.5.2 取樣：在特定時間記錄數值

數位化包含兩個動作。

**取樣（sampling）**是每隔固定的時間量一次訊號的振幅。原本連續的波形，變成一連串在特定時間點上的測量值。

**量化（quantization）**是把量到的振幅對應到可以表示的數值。測量結果不能有無限的精細度，必須落在一組有限的數字上。

做完這兩件事，程式手上就只剩一串數字。波形圖是我們畫給人看的，程式看到的是依時間排列的取樣值，此外沒有別的東西。這句話值得記住，因為後面所有的處理都是在對這串數字做運算。

## 4.5.3 取樣率與混疊

**取樣率（sample rate）**是每秒取樣幾次。48 kHz 表示每個聲道每秒取樣 48,000 次，取樣間隔是 1 ÷ 48000，大約 20.83 微秒。另一個常見的值是 44.1 kHz，來自 CD 規格，間隔約 22.68 微秒。兩者都在用，沒有誰比較正確。

取樣點太疏會出問題。當訊號的頻率相對於取樣率太高，取樣點連起來會呈現出**另一個較低的頻率**，而且從取樣結果無法分辨原本是哪一個。這個現象叫做**混疊（aliasing）**。

理想帶限條件下，取樣率必須高於訊號最高頻率的兩倍。這個結果稱為**取樣定理（sampling theorem）**，也常寫作 Nyquist–Shannon 取樣定理。

由它可以定出一個很常用的量：取樣率的一半，是這個系統能正確表示的最高頻率，稱為 **Nyquist 頻率**。48 kHz 的 Nyquist 頻率是 24 kHz，44.1 kHz 是 22.05 kHz。人耳的上限大約在 20 kHz，這就是 CD 選 44.1 kHz 的理由。

有兩個相近的詞經常被混用，分開記比較不會亂：

| 名稱 | 定義 | 由什麼決定 |
|---|---|---|
| Nyquist 頻率 | 取樣率的一半（fs / 2） | 取樣系統 |
| Nyquist rate | 訊號最高頻率的兩倍 | 訊號本身 |

前者是「這個系統最高能表示到哪裡」，後者是「這個訊號要求取樣率至少多少」。第 7 章講 Pd 的取樣率時用的是前者。

超過 Nyquist 頻率的成分不會憑空消失，而是被折回低頻區，變成前面說的混疊。實務上不會期待輸入訊號自己乖乖不超過上限，而是在 ADC 之前加一道**抗混疊濾波器（anti-aliasing filter）**，先把過高的頻率濾掉再取樣。

## 4.5.4 位元深度與量化

**位元深度（bit depth）**決定振幅可以分成多少階。在固定整數的 PCM 格式中，b 個 bit 可以表示 2 的 b 次方個碼值，16-bit 就是 65,536 階。

階數越多，量化誤差越小，但誤差不會變成零。任何有限的階數都會讓實際值和記錄值之間存在差距，這個差距就是量化誤差。

這裡有一個常見的誤解要先擋掉：教科書上把量化畫成階梯狀的波形，那是示意圖，用來讓誤差看得見。經過 DAC 與重建濾波之後的類比輸出，並不會真的長成階梯狀。

取樣率和位元深度描述的是不同的東西，不能互相換算。取樣率講的是**時間**上的取樣密度，畫在圖上是水平方向的間隔；位元深度講的是**振幅**的表示精細度，畫在圖上是垂直方向的階。把取樣率加倍，量化誤差不會因此變小。

## 4.5.5 完整的訊號鏈

把前面幾節接起來，從聲音到數字再回到聲音的路徑是這樣：

麥克風把聲波轉成電壓，**ADC（類比數位轉換器）**做取樣與量化，數位處理在這裡進行，**DAC（數位類比轉換器）**把數值還原成電壓，經過重建濾波之後推動喇叭。

程式站在這條鏈的中間，拿到的是一串依時間排列的取樣值。

到這裡有一個問題冒出來：每個聲道一秒就有 48,000 筆資料，程式要一筆一筆交給音效裝置嗎？

## 4.5.6 為什麼要分批處理

答案是不會，原因有兩個。

第一個原因是時間。音效裝置依固定的時鐘持續播放，它不會等人。但 CPU 的執行與排程會波動，作業系統隨時可能把時間分給別的工作。即時音訊的要求不是「快」，而是**準時**：每一批資料都必須在裝置需要它之前準備好。平均速度很快但偶爾遲到，聽起來就是爆音。

第二個原因是開銷。每一次呼叫與資料傳遞都有固定成本，逐筆交付等於把這個成本付 48,000 次。分批交付可以把它攤薄。要注意的是，分批省下的是「交付」的次數，不是運算量。批次之內程式仍然是一筆一筆算。

這裡有兩個容易混用的詞。**buffer** 是存放待處理或待播放資料的空間，**block** 是一次處理的資料區塊。處理大小、儲存容量、實際排隊的資料量是三件不同的事。

要留意的是，Max/MSP 的 `[buffer~]` 物件指的是「載入音檔用的記憶體」，和這裡講的 I/O 緩衝不是同一個概念。第 8 章會遇到它。

分批之後的運作方式，最小的模型是雙緩衝：硬體在讀已經算完的那一塊時，程式同時準備下一塊，兩塊輪流交換角色。真實的音訊堆疊通常不只兩層。

## 4.5.7 Buffer 大小的取捨

計算區塊時長之前要先分清楚 frame 和 sample。同一個時間點上所有聲道的取樣合起來算一個 **frame**。立體聲的 256 frames 包含 512 個取樣值，但時長仍然是 256 個取樣間隔。

區塊時長的算法是 `T = N / fs`，N 是 frames 數，fs 是取樣率。取樣率 48 kHz 時：

| 區塊大小 | 區塊音訊時長 |
|---:|---:|
| 64 frames | 1.33 ms |
| 128 frames | 2.67 ms |
| 256 frames | 5.33 ms |
| 512 frames | 10.67 ms |
| 1024 frames | 21.33 ms |

把 buffer 調小，通常能減少緩衝造成的延遲。代價是呼叫變得更頻繁，而且每一次處理的期限更短，對時間波動更敏感。即時演奏、監聽自己的歌聲，這類場合才需要把它壓小。

把 buffer 調大，固定開銷比較容易攤薄，也比較能容忍短暫的運算尖峰。代價是排隊等著播放的資料變多，等待也跟著增加。非即時的混音與離線輸出用大 buffer 反而省事。

有一件事調大 buffer 救不了：如果 CPU 的運算能力持續不足，那不是餘裕的問題。buffer 是用來吸收短暫尖峰的，不是用來補結構性的算力缺口。

交付不及會產生兩種狀況。**underflow** 是輸出資料供應不及，音效裝置沒有東西可播，結果是缺口與爆音。**overflow** 是輸入資料來不及取走，緩衝空間被塞滿。

即時系統看的是最壞情況而不是平均值。CPU 使用率顯示只有 30%，仍然可能因為單次運算尖峰超過期限而斷音。

## 4.5.8 延遲不只來自 buffer

區塊時長不等於總延遲。把 buffer 設成 256 frames，不代表從麥克風到喇叭就是 5.33 毫秒。

實際的延遲沿路累積：輸入緩衝、ADC、驅動、演算法本身、輸出緩衝、DAC，每一段都有貢獻。用單一 buffer 的時長去推算整條路徑會嚴重低估。

還有一個容易混淆的地方是，軟體向系統「要求」的延遲值，和實際量到的延遲是兩回事。PortAudio 的串流參數文件對這個區別有清楚的說明，是不錯的參考。

## 4.5.9 接下來

Pure Data 把音訊運算組成 DSP 網路，並且分塊執行。下一章開始建立第一個振盪器，調整振幅，把聲音送出去：

```
[osc~ 440]      <- 產生 440 Hz 正弦波
|
[*~ 0.1]        <- 把振幅降到 0.1
|
[dac~]          <- 送到音效輸出
```

> ⚠️ Pd 內部的 DSP block size，和音訊裝置的 I/O 緩衝設定，屬於不同層次。實際操作時要分開理解，不然會把兩個設定混在一起調。
