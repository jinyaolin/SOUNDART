# 兩個工具的比較與選擇

第 8 章 8.7 節已經給過一張速查對照表。這一章要回答的是更前面的問題：**你到底該用哪一個，以及什麼時候該兩個都不用。**

---

## 9.1 先說結論

如果你只想要一個答案，這是我的建議：

> **先學 Pure Data。**
> 它免費、跨平台、原理最裸露，而且能嵌進別的東西裡。
> **等到你遇到 Pd 做不到的事，再去學 Max——那時候你只需要一個下午。**

理由很簡單：**這兩個工具的核心心智模型是同一個**（同一個人設計的）。真正花時間的是理解「訊號與訊息」「hot / cold」「右到左」「`~` 的分界」，而那些東西在哪一邊學都一樣。剩下的差異是物件名稱與功能廣度——**查表就好**。

反過來說，如果你的處境符合下面任一項，**直接學 Max 比較省事**：

- 學校／單位已經買了授權，而且同學都在用
- 你的作品**一定會用到影像**（Jitter 遠比 GEM 成熟）
- 你已經是 Ableton Live 使用者，想做 Max for Live 裝置
- 你要接的硬體有現成的 Max 支援套件

## 9.2 逐項比較

| 面向 | Pure Data | Max/MSP | 說明 |
|---|---|---|---|
| **授權費用** | 免費、開源（BSD） | 商業，需購買（有試用與教育價） | 對學生與長期專案，這一項的重量比想像中大 |
| **安裝門檻** | 低（PlugData 一鍵） | 低 | 平手 |
| **學習資源** | 少而分散 | 多，且**每個物件都有可執行的說明檔** | Max 明顯勝 |
| **內建物件** | 少而精 | 多，且品質一致 | Max 勝 |
| **介面美感** | 樸素（PlugData 改善很多） | 精緻，可做出交付級的 UI | Max 勝 |
| **影像／3D** | GEM（外掛，較難裝） | **Jitter**（內建、成熟） | Max 大勝 |
| **音訊品質** | 相同 | 相同 | **兩者的 DSP 沒有本質差異** |
| **穩定性** | 高，極少崩潰 | 高 | 平手 |
| **可嵌入性** | **libpd / hvcc**，可進 App、遊戲、微控制器 | RNBO（較新、需訂閱） | **Pd 大勝** |
| **與 DAW 整合** | PlugData（VST3） | Max for Live（深度整合 Ableton） | 看你用哪個 DAW |
| **社群** | 學術、實驗、DIY、嵌入式 | 商業、裝置藝術、劇場、音樂製作 | 看你想跟誰對話 |
| **檔案格式** | 純文字 `.pd`，可用 git diff | `.maxpat` 是 JSON，可讀但難 diff | Pd 對版本控制友善 |
| **長期保存** | 開源，二十年後還開得起來 | 依賴商業公司持續營運 | 做典藏級作品時要考慮 |

### 幾個容易被誤解的地方

**「Max 的音質比較好」——不是。**
兩者的 DSP 都是 32-bit 浮點、同樣的演算法。差別在**內建工具的多寡**，不在聲音本身。

**「Pd 比較難」——也不完全對。**
Pd 的困難來自**資源少**與**內建物件少**（很多東西要自己接）。但也正因為要自己接，你會更清楚它在做什麼。教學上這常常是優點。

**「學了一個就白費另一個」——完全不會。**
見 9.4 節。

## 9.3 五個真實情境該怎麼選

### 情境一：展場的互動聲音裝置

**接感測器、可能要影像、要跑三個月不當機、要有人能來現場調參數。**

→ **Max/MSP**，除非預算是零。

理由：Jitter、`[serial]`、`[udpreceive]` 的支援與說明文件成熟；Presentation Mode 可以做出讓策展人／志工看得懂的介面；出問題時有較多人能幫你。

> 但如果作品要**長期典藏**（十年後還要能重新佈展），Pd 的開源特性反而是優勢——這是美術館典藏部門真的會問的問題。

### 情境二：手機 App、遊戲、或要塞進硬體

→ **Pure Data，沒有第二個選擇。**

`libpd` 可以嵌進 iOS／Android／Unity／Unreal；`hvcc`（Heavy 編譯器）可以把補丁編譯成 C，跑在 Raspberry Pi、Bela、Daisy 這類微控制器上。

第 4 章 4.8 節的《Spore》就是這條路。**Max 的 RNBO 是近年才補上的對應方案，生態與資源仍少得多。**

### 情境三：課堂教學

→ **Pure Data（PlugData）。**

全班零成本、跨平台一致、學生回家繼續做不用煩惱授權。而且教「原理」時，物件少反而是好事——**沒有現成的 `[adsr~]`，學生就得自己用 `[vline~]` 拼出包絡，於是他真的懂了包絡是什麼。**

### 情境四：現場演出

→ **兩者都行，看你的訊號鏈。**

如果你用 Ableton Live 當骨幹 → **Max for Live**，無縫。
如果你要獨立的、開機就跑的系統 → **Pd**，尤其可以跑在一台便宜的小電腦上當黑盒子。

### 情境五：學術研究與論文

→ **Pure Data**，通常比較適合。

開源代表**可重現**：審查者與後人可以真的打開你的補丁重跑一次。`.pd` 是純文字，可以放進論文附錄、放進 git、做 diff。

## 9.4 兩者共通的心智模型（這才是你真正在學的東西）

換工具時，這些**一個字都不用重學**：

| 觀念 | Pure Data | Max/MSP |
|---|---|---|
| `~` 代表音訊 | ✓ | ✓ |
| 訊號線比較粗，訊息線比較細 | ✓ | ✓ |
| 最左邊是 hot inlet，其他是 cold | ✓ | ✓ |
| 一個 outlet 接多個目標時，**從右到左** | ✓ | ✓ |
| 多條訊號接同一個 inlet 會**自動相加** | ✓ | ✓ |
| 用 `[trigger]` / `[t]` 明確指定順序 | ✓ | ✓ |
| 子補丁與抽象用來組織複雜度 | ✓ | ✓ |
| `[send]` / `[receive]` 無線傳輸 | ✓ | ✓ |
| 合成原理（加法／減法／FM／取樣／延遲） | ✓ | ✓ |

> **這九條佔了你學習時間的九成。**
> 剩下那一成是物件名稱——第 8 章 8.7 節的對照表就夠了。

## 9.5 檔案能不能互通？

**簡短的答案：不能直接互通，但有幾條路。**

- **Pd 補丁不能在 Max 裡開，反之亦然。** 兩者的檔案格式與物件集不同，沒有官方轉換工具。
- **`cyclone` 函式庫**把許多 Max 常用物件名（`[gate]`、`[speedlim]`、`[zl]` 等）帶進 Pd，讓 Max 使用者移植概念時輕鬆很多。
- **PlugData** 讓 Pd 補丁能以 VST3 形式在任何 DAW 裡跑。
- **`hvcc`（Heavy）** 把 Pd 補丁編譯成 C／JavaScript／外掛，可跑在遊戲引擎與嵌入式硬體。

> **實務上，你移植的是想法而不是檔案。**
> 一個減法合成器的補丁，兩邊都是「振盪器 → 濾波器 → 包絡乘音量」，
> 重接一次通常比找轉換工具快。

## 9.6 什麼時候該離開這兩個工具

視覺化程式語言不是萬能的。以下情況值得考慮別的路：

| 情況 | 建議 |
|---|---|
| 補丁大到你自己看不懂了 | **SuperCollider**（文字、可寫函式與迴圈）或 **Csound** |
| 需要極高效率、逐取樣點運算 | Max 的 **`gen~`**、Pd 的 **`expr~`**，或直接寫 C／C++ |
| 要在瀏覽器裡跑 | **Web Audio API**、**WebPd**、或 RNBO 匯出的 JavaScript |
| 要做成商業外掛 | **JUCE**（C++），或 RNBO／hvcc 匯出 |
| 只是要做音樂，不是做工具 | **老老實實用 DAW。** 用 Pd 做一首歌通常是浪費生命 |

> **最後一項最重要。** 這兩個工具的價值在於**做出別的軟體裡不存在的東西**。
> 如果你想做的事情 Ableton 三分鐘就能做完，那就用 Ableton。

---

## 9.7 小結

**選工具的順序應該是：先確定作品要什麼，再回頭選工具。** 反過來做——先愛上一個工具，再找題目給它做——是初學者最常見的陷阱。

三句話：

1. **免費、要嵌入、要教學、要可重現 → Pure Data**
2. **要影像、要接硬體、要交付給別人操作、要進 Ableton → Max/MSP**
3. **兩個都學一點的成本，比你以為的低很多**——因為你學的其實是同一套東西
